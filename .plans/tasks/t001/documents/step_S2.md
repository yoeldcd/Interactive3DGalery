# SP3 — Domain and Application Contracts

This specification is normative. Names, fields, parameter types, return types and invariants below must be implemented literally unless an execution-history entry records an approved modification.

## 1. Primitive Types and Value Objects

### 1.1 Entity ids — `src/domain/value-objects/EntityIds.ts`

```ts
export type GalleryId = string & { readonly __brand: 'GalleryId' };
export type RoomId = string & { readonly __brand: 'RoomId' };
export type PictureId = string & { readonly __brand: 'PictureId' };
export type AssetId = string & { readonly __brand: 'AssetId' };

export function asGalleryId(value: string): GalleryId;
export function asRoomId(value: string): RoomId;
export function asPictureId(value: string): PictureId;
export function asAssetId(value: string): AssetId;
export function isUuid(value: string): boolean;
```

Rules:

- Accepted ids match UUID format generated by `crypto.randomUUID()`.
- Conversion validates and throws `DomainError('INVALID_ID', ...)`; it does not generate ids.
- Branded types are erased at runtime and serialize as strings.

### 1.2 Hex colors — `src/domain/value-objects/HexColor.ts`

```ts
export type HexColor = string & { readonly __brand: 'HexColor' };

export function createHexColor(value: string): HexColor;
export function isHexColor(value: string): value is HexColor;
```

Rules:

- Canonical format is uppercase `#RRGGBB`.
- `#RGB`, alpha, named colors, CSS functions and whitespace are rejected.

### 1.3 Text fields — `src/domain/value-objects/TextFields.ts`

```ts
export function normalizeRequiredName(
  value: string,
  field: 'galleryName' | 'roomName' | 'pictureName',
): string;

export function normalizeDescription(value: string): string;
export function normalizeLinkLabel(value: string | null | undefined): string | null;
export function slugifyFileName(value: string): string;
```

Rules:

- Trim outer whitespace and collapse internal whitespace runs to one space for names.
- Gallery/room/picture names: `1..120` Unicode code points.
- Description: trim only; maximum `2000` code points; empty allowed.
- Link label: trim; maximum `120`; empty becomes `null`.
- Slug: lowercase ASCII approximation, hyphen separated, max `80`; fallback `gallery`.

### 1.6 Asset references — `src/domain/value-objects/AssetRef.ts`

```ts
export type AssetKind = 'image' | 'wall-texture' | 'audio' | 'obj';

export interface LocalAssetRef {
  readonly source: 'local';
  readonly id: AssetId;
  readonly kind: AssetKind;
  readonly fileName: string;
  readonly mimeType: string;
  readonly byteLength: number;
}

export interface RemoteAssetRef {
  readonly source: 'remote';
  readonly kind: AssetKind;
  readonly url: string;
}

export type AssetRef = LocalAssetRef | RemoteAssetRef;

export function createLocalAssetRef(input: {
  id: AssetId;
  kind: AssetKind;
  fileName: string;
  mimeType: string;
  byteLength: number;
}): LocalAssetRef;

export function createRemoteAssetRef(kind: AssetKind, url: string): RemoteAssetRef;
export function isLocalAssetRef(ref: AssetRef): ref is LocalAssetRef;
```

Rules:

- `fileName`: trimmed, basename only, `1..255` code points.
- `mimeType`: lowercase trimmed string; may be `application/octet-stream` only when extension validation has passed.
- `byteLength`: finite integer `>0` and within `Number.MAX_SAFE_INTEGER`.
- Remote URLs accept only `http/https`, no credentials.
- `kind` must match field usage; e.g. picture cannot hold `audio`.

### 9.1 Store — `src/application/ports/GalleryStore.ts`

```ts
export interface GalleryCommit {
  readonly snapshot: GallerySnapshot;
  readonly putAssets: readonly AssetWrite[];
```

Commit requirements:

- `snapshot`, `putAssets`, deletions and current-gallery meta write share one readwrite IndexedDB transaction.
- A put id cannot also appear in delete list.

### 10.3 Commit planner — `GalleryCommitPlanner.ts`

```ts
export class GalleryCommitPlanner {
  public constructor(private readonly collector: GalleryAssetReferenceCollector);

  public plan(input: {
    before: GallerySnapshot | null;
    after: GallerySnapshot;
    newAssets?: readonly AssetWrite[];
  }): GalleryCommit;
}
```

Algorithm:

1. Collect local ids before/after.
2. Validate every new asset id appears in `after`.
3. Validate no new asset id existed before.
4. Delete `beforeIds - afterIds`.
5. Never delete an id still referenced elsewhere.
6. Sort puts/deletes by id for deterministic tests.

## 11. Use Cases

Every mutating use case follows this sequence:

1. Load required snapshot/entity.
2. Validate/materialize command.
3. Apply domain mutation.
4. Call `gallery.touch(clock.nowIso())` exactly once.
5. Plan commit against original snapshot.
6. `await store.commit`.
7. Return committed `GallerySnapshot`.

No use case updates UI state directly.

- `remove`: set nullable sound/object to null; invalid for texture when wall mode is texture.
- `replace`: materialize new local/remote ref.
- When wall switches to color, prior local texture becomes unreferenced and commit planner deletes it.
- `backgroundVolume` is ignored only when sound resolves to null.
- `objectScale` is validated even if object resolves null, but omitted from snapshot until an object exists.

Remapping algorithm:

1. Parse package into validated old room + assets.
2. Generate new room id.
3. Generate one new picture id per picture.
4. Generate one new asset id per local archive asset.
5. Rewrite all local refs through mapping; reject missing mappings.
6. Resolve duplicate room name with suffix.
7. Add room, touch, commit snapshot + rewritten asset writes.
